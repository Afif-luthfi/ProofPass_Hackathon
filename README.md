# ProofPass

ProofPass records wallet claims and document fingerprints on BOT Chain. This repository currently contains the Solidity contract, automated tests, and a local MetaMask diagnosis/deployment utility. It is not yet the complete skill-passport application described in [the PRD](PRD-ProofPass.md).

The utility compares the chain ID and genesis block returned by MetaMask with the configured official BOT RPC. It reads the selected wallet's testnet and mainnet balances independently. This avoids relying on wallet token filters or Remix's displayed ETH label when identifying a network.

## Run locally

Use Node.js 22.13+ (tested with 24.17.0) and a browser containing the MetaMask extension.

```sh
npm ci
npm start
```

Open http://127.0.0.1:4173 in the same browser/profile where MetaMask is installed. The application binds only to the local computer. The browser inside an AI desktop app may not have the MetaMask extension.

1. Connect MetaMask. No signature or transaction is needed for this connection.
2. Read the independent testnet and mainnet balances.
3. Select BOT Chain Testnet and click the button to switch MetaMask to that network for this site.
4. Check the deployment cost. The tool verifies chain identity and sufficient balance first.
5. Review the network and fee, tick the confirmation, then request deployment.
6. Review and approve the actual transaction in MetaMask. Contract creation sends **zero BOT value** but costs gas.
7. Check the transaction status. The tool confirms the receipt, sender, creation bytecode and deployed runtime through the official RPC.
8. Download the deployment record. Refreshing does not submit a second transaction.

Mainnet deployment in this utility requires a verified testnet deployment of the same compiled contract first. Testnet BOT cannot pay mainnet gas. Request a mainnet BOT allocation from the hackathon organizer if needed.

No seed phrase, private key, password, faucet redemption code, or API key is required by this tool. Signing takes place only in MetaMask. A confirmed connection alone does not approve deployment.

## Contract

Source: [contracts/ProofPass.sol](contracts/ProofPass.sol).

- `registerProof(metadataHash, documentHash, hasDocument)`: registers an append-only claim under `msg.sender` and returns a globally unique ID starting at 1.
- `getProof(id)`: returns recorder, blockchain timestamp, document presence, and hashes; nonexistent IDs revert.
- `proofCount(recorder)` and `getProofIds(recorder, offset, limit)`: list that wallet's records, at most 100 IDs per request.
- `ProofRegistered`: emits the ID, recorder, metadata hash, optional document hash, presence flag and timestamp.
- Identical payloads from the same wallet are rejected to reduce accidental duplicate registrations. Another wallet cannot prevent the first wallet from registering its own claim.
- There is no administrator, upgrade mechanism, deletion function, issuer verification, token minting, withdrawal or payable entry point.

Use SHA-256 of original file bytes for `documentHash`. For text-only claims pass the zero hash and `hasDocument=false`. Use a nonzero digest of deterministically serialized metadata for `metadataHash`; the future application must specify its serialization schema. The contract stores hashes without knowing their preimages or authenticating their meaning.

A matching hash establishes byte equality with a registered document, not document authenticity, identity, ownership or an institution's endorsement. The block timestamp is the registration time, not the achievement date.

## Build and validation

```sh
npm run compile
npm test
npm run test:browser
npm run check:networks
npm audit
```

The browser suite uses an installed Chrome and a clearly isolated mock wallet in temporary test contexts. It never opens or signs through a user's real MetaMask. Contract tests run on an in-memory Hardhat chain using disposable development accounts.

Compilation uses pinned Solidity 0.8.37, optimizer enabled with 200 runs, and EVM `paris` to avoid depending on newer opcodes. Outputs are `artifacts/ProofPass.json` (ABI and bytecode) and `artifacts/solc-input.json` (standard compiler input). Both are generated by `npm run compile`.

To compile in Remix if desired: copy `contracts/ProofPass.sol`, select compiler **0.8.37**, EVM **Paris**, and optimizer **enabled, 200 runs**. There are no constructor arguments. Merely displaying `ETH` is not reliable evidence of the connected chain; check `eth_chainId` and the RPC identity.

The exact versions are locked in `package-lock.json`. The solc `tmp` dependency is overridden to 0.2.7 to address the published advisory affecting 0.2.6.

## Boundaries and troubleshooting

- RPC reads and gas simulation use a fixed, read-only local proxy. The server cannot sign or broadcast a transaction and does not expose arbitrary workspace files.
- Receipts are kept in this browser's local storage. They are not the future application's persistent metadata database. Use the download button to back up a confirmed deployment.
- If the wallet changes or an estimate becomes older than two minutes, review again.
- If a request times out after wallet approval, inspect MetaMask activity/explorer before retrying. Use the transaction-hash recovery form for a deployment already sent.
- The tool checks one mined successful receipt and exact runtime code; it does not claim economic finality. Check the explorer again before publishing the address.
- No public website, AI API integration, file uploads, metadata backend, or credential issuer verification is implemented in this deployment kit.
- Stopping the local server makes the utility unavailable until `npm start` runs again. Restart with Ctrl+C and `npm start` after changing server code.
